# Upgrade: Jumbotron 0.2.0

**From:** `0.1.7`  
**To:** `0.2.0`

Minor release: named NFL sandbox projection and Reset/reprojection behind the public client. ESPN `espn_nfl` read and update contracts are unchanged.

## Host-facing change

| Change | Host impact |
|--------|-------------|
| `sandbox_nfl` adapter | In-process NFL sandbox adapter (`league: nfl-sandbox`) with the same Game/Line policy set as ESPN. Not ESPN I/O. |
| `Jumbotron.client.register_sandbox_projection` | Idempotent named bind of a sandbox to immutable source selectors. Rejects conflicting redefinition. |
| `Jumbotron.client.reset_sandbox_projection` | Whole-season Reset: Eastern calendar-day shift, stable source→sandbox game mappings, complete projection or no commit. |
| Sandbox public errors | Structured `code` + safe `details` on public exceptions (`SandboxResetRejectedError` and mapped sandbox failures). |
| Recurring schedules | Desired schedules now include `jumbotron:sandbox_nfl:*` policy keys (still no `full_season` discovery cron). |
| Temporary `json < 3` gemspec constraint | Bundler will refuse json 3.x for any host that depends on this gem. Not a Jumbotron API change. See below. |

## Upgrade checklist

1. Bump gem to `0.2.0` (or `>= 0.2.0`).
2. Copy engine migrations and migrate:

   ```bash
   bin/rails jumbotron:install:migrations
   bin/rails db:migrate
   ```

   New engine files:

   - `20260908000001_create_jumbotron_sandbox_game_plans.rb`
   - `20260908000002_create_jumbotron_sandbox_projections.rb` (also creates `jumbotron_sandbox_game_mappings`)

3. Rematerialize Solid Queue recurring YAML so `jumbotron:sandbox_nfl:*` keys appear if the host should run sandbox polls:

   ```bash
   bin/rails jumbotron:schedules:materialize
   ```

   Host-owned keys (`pickem:*`, `clear_solid_queue_finished_jobs`) are preserved. ESPN `jumbotron:espn_nfl:*` keys are unchanged.

4. Optional: register then Reset a named projection from a host (no HTTP in Jumbotron):

   ```ruby
   Jumbotron.client.register_sandbox_projection(name: "nfl-sandbox", source: "nfl")
   Jumbotron.client.reset_sandbox_projection(
     sandbox: "nfl-sandbox",
     start_week: 1,
     anchor_day: 1,
     now: Time.current.iso8601
   )
   ```

## Temporary `json < 3` constraint

**Why.** json 3.0 made `JSON.parse` keyword-only. Released Rails 8.1.3.1 still does `JSON.parse(json, options)` with a positional Hash (default `{}` even when callers pass no options). That raises `ArgumentError: wrong number of arguments (given 2, expected 1)` on every `ActiveSupport::JSON.decode`, including ActiveRecord `:json` attributes (`ObservationBatch`, `LineObservation`, `HistoricalChange`) and ActionDispatch JSON request bodies.

A Gemfile pin in this engine repo only protects dummy-app CI. Hosts (Pick'em, others) resolve `json` from their own lockfiles. Putting `json < 3` in the **gemspec** makes Bundler enforce the ceiling wherever Jumbotron is a dependency.

This is a workaround for a Rails/json incompatibility, not a Jumbotron product dependency. Rails main / `8-1-stable` already splat (`JSON.parse(json, **options)`); no Rails gem that includes that fix was published at 0.2.0 (`8.1.3.1` is still latest).

**Undo when all of the following are true:**

1. A Rails gem is released whose `ActiveSupport::JSON.decode` calls `JSON.parse(json, **options)` (or equivalent: no positional options Hash). Confirm in that gem's `activesupport/lib/active_support/json/decoding.rb`.
2. Every Jumbotron host is on that Rails version (or newer). Pick'em today is `~> 8.1.3`, `>= 8.1.3.1`.
3. Then remove `spec.add_dependency "json", "< 3"` from `jumbotron.gemspec`, `bundle install` in Docker, drop this section, and drop the packaging example that asserts the ceiling.

Do not undo just because a host Gemfile pins json, or because Jumbotron CI happens to lock 2.x.

## What is not in this release

- No ESPN public Game/Schedule/Consensus/CurrentLines contract change.
- No Pick'em competitive domain. Hosts own whether they materialize sandbox seasons and whether production runs `sandbox_nfl` polls.
- No new `full_season` discovery job for sandbox (sandbox catalog is projected, not ESPN-discovered).
